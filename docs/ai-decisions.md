- 2026-06-14: Prepare for Cloudflare Workers/Pages migration using `@cloudflare/next-on-pages` adapter. Rationale: Vercel limits hit, Cloudflare provides better cost/performance at scale, adapter preserves Next.js App Router patterns. Key findings: 9 files with `fs` usage (biggest blocker), `pg` driver incompatible (needs Hyperdrive or serverless driver), `@xenova/transformers` must stay disabled in Workers. Migration approach: phased — (1) pre-bundle JSON at build time to eliminate fs reads, (2) switch pg to HTTP-based driver or Hyperdrive, (3) enable `nodejs_compat` flag for crypto/Buffer, (4) deploy to Cloudflare Pages. Deferred: full edge migration of all routes (some routes may stay Node.js-only initially), local embeddings path remains Vercel/Node.js only.

- 2026-06-14: Cloudflare migration target is Cloudflare Workers via `@opennextjs/cloudflare`, not legacy `@cloudflare/next-on-pages`. Large runtime JSON must be prepared as private R2 runtime-data shards instead of bundled into the Worker; small config data may still be bundled when safe.
- 2026-06-14: Feedback writes use Supabase HTTP client/RLS instead of direct `pg` in runtime so the route can run on Cloudflare Workers without TCP Postgres access.
